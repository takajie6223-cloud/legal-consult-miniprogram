4. 已知不足与后续建议

事项影响现象与定位建议
法条通道对纯口语问句返回空中「欠钱不还」「辞退赔偿」「噪音扰民」在 /api/laws/search 返回 0 条。这是 lawsearch.py 里刻意加的闸门：整批候选只靠同义词沾边时不硬凑，交给类案向量通道。接口不报错、答案也不会空，但这一类高频问句拿不到法条引用卡片。为高频口语问句补一层「问句 → 目标法条」映射（欠钱不还 → 民法典第667/675条，辞退赔偿 → 劳动合同法第46/47条），或在类案通道里同时回带法条。
「房租押金不退」排序被无关规章占位中同义词把「押金」扩成「保证金 / 返还」，结果《人民检察院刑事诉讼规则》几百条审判监督条文冲到 Top，民法典第577条（违约责任）没进前列。原因是核心法正则 CORE_RE 用子串匹配，「刑事诉讼」把检察规则也判成了核心法。CORE_RE 改成按法名精确匹配（或加黑名单排除检察/公安程序规定），并对同义词命中设更低权重上限。
时效结果依据里民法典第188条重复已修复civil3 / max20 的期间依据本身就是民法典第188条，代码又在固定依据列表里写了一次，所以 /api/limit 返回的 citations 出现两条同号条文。backend/app/services/limcalc.py 在取依据前按 (法名, 条号) 去重；本次跑批已按「条号不重复」重新校验通过。
追问建议依赖本地模型，超时即退题库低/api/followups 给模型 12 秒窗口，超时就退回领域题库模板。功能不会空，但低配机器上建议文案会偏通用。如需更稳定的个性化追问，可把 OLLAMA_KEEP_ALIVE 设为非零，避免模型每次冷加载。
诊断提示线与开发者工具代理为临时配置低首页残留一条黄色诊断文案；微信开发者工具代理被临时改成 DIRECT 以便本机直连 9100。体验前删除诊断文案并把代理还原为 SYSTEM。
跑批会话与真实记录同属一个用户低后端未配置微信 appid/secret，登录走 dev 游客模式，所有测试会话都落在同一个 user_id 下，与真实咨询混在「记录」页同一列表里。本次跑批结束后按出题原文前缀回收了 77 条测试会话（真实记录 29 条未受影响），回收前的库快照已留存在项目外的本地目录，可随时还原。正式使用前配置真实 appid/secret 让 openid 区分用户；或给测试环境单挂一份 law.db。
